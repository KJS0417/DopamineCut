# 목표 추천·알림·변화·설정 구현

## 1. 반영 범위

| 항목 | 이전 | 변경 |
|---|---|---|
| 추천 기준 | 데이터 공급자 없음 | 완료된 유효 날짜 3~7일, 오늘·부분 측정일 제외 |
| 추천 단계 | 예시 버튼 | 줄이기 15% / 더 줄이기 30% / 도전 50% |
| 목표 상세 | 복수 목표가 앱·개입 설정 공유 | 각 목표의 앱·개입 설정 독립, 평균·감소량·비율·조건부 주간 환산 |
| 목표 목록 | 한도·상태만 표시 | 오늘 사용량, 저장 당시 고정 비교 기준, 예상 변화 표시 |
| 자동 알림 | 설정만 저장 | 기기 내 예약·조건 평가·발송 이력·인증된 화면 이동 연결 |
| 내 변화 보기 | 미연동 안내 | 전날 사용 변화, 고정 기준 대비 수행 평균, 목표별 달성률·품질 경고 |
| 설정 | 분석·삭제 비활성 | 기록 중지·재개, OCR/분류 선택, 오늘·전체 사용 기록 삭제 |

추천 선택은 입력값을 채울 뿐이다. 사용자가 목표 저장을 눌러야 활성화된다. 앱 사용시간과 숏폼 시간의 절감량은 합산하지 않는다.

## 2. 기준 데이터와 추천

- 서비스는 화면이 켜진 동안 관측한 시간을 단조 시계로 누적한다. 30초마다 사용자·날짜별 로컬 품질 기록을 남긴다.
- Android 사용정보의 화면 켜짐 이력을 조회해 예상 관측 시간과 비교한다. 관측 비율 90% 이상이며 미확인 구간 비율이 허용 범위 안인 날만 사용한다.
- 첫 측정일은 부분 하루일 수 있어 제외한다. 시작 후 72시간 이상, 완료된 유효 날짜 3일 이상이 필요하다. 따라서 정확히 3일째 제공을 보장하지 않는다.
- 화면 상태 이력을 확인할 수 없는 기기·날짜, 품질 이력이 없는 기존 데이터는 유효하다고 추정하지 않는다. 직접 목표 설정은 계속 가능하다.
- 완료된 유효 날짜가 존재할 때 해당 앱 사용이 0이면 0으로 계산한다. 날짜 기록 자체가 없으면 0으로 채우지 않는다.
- 최신 최대 7개 유효 날짜의 평균을 사용한다. 앱별 값을 합산해 해당 카드 범위의 평균을 구한다.
- 최종 목표값은 `ceil(평균 × (1 - 감소율))`로 정수 단위 올림한다. 화면의 실제 감소율은 최종 한도로 다시 계산한다. 설정 최대값을 넘는 추천은 비활성화한다.
- 목표 저장 당시 날짜·평균을 로컬에 고정한다. 사용량 증가나 추천 갱신으로 목표를 자동 변경하지 않는다.

## 3. 목표 화면

1. 숏폼 시간·영상 수·앱 사용시간을 복수 선택한다.
2. 각 카드의 `앱·개입 설정`을 눌러 해당 카드의 적용 앱과 개입 방식을 선택한다.
3. 유효 기준이 있으면 세 감소안을 선택하거나 최종 한도를 직접 입력한다.
4. 기준 기간·평균과 하루 감소량·감소율·7일 모두 달성 시 환산을 확인한다.
5. 저장하면 오늘 누적량을 유지한 채 즉시 적용한다. 0 한도와 제한 방식은 별도 확인한다.

숏폼 시간 목표에는 연속 시청 휴식 안내를 0~180분으로 선택할 수 있다. 0은 끄기다. 실제 확정 숏폼을 연속으로 보는 구간에서 한 번 안내한다. 광고·미확인·오버레이 시간은 증가시키지 않는다. 기록만 보기 또는 목표 진행 알림 해제 상태에서는 발송하지 않는다.

중지·복원 시 기존 한도와 고정 기준을 유지하며 중지 기간은 목표 평가에서 제외한다. 시작·수정·복원 당일은 온전한 하루 성과로 간주하지 않는다.

## 4. 알림

| 종류 | 연결된 처리 |
|---|---|
| N01 | 첫 추천 준비 시 1회, 반복 권유하지 않음 |
| N02·N03 | 기존 시청 서비스의 목표 임박·도달 개입 유지 |
| N04 | 도달 안내 이력 이후 실제 사용 지속, 10분/10회 추가 초과와 60분 이상 간격, 목표·날짜별 후속 1회 |
| N05 | 선택한 연속 숏폼 시청 한도에 도달하면 구간당 1회 |
| N07·N08·N11·N12 | 오전 08시 후보 순서를 무작위로 한 번 저장하고 한 개 선택 |
| 점심 12시 | 오전 미처리 후보 한 개, 없으면 N13·N14 중 한 개 |
| N09·N10 | 21시 이전 누적 기록끼리 비교, 절대 차이 10분 이하 미발송, 증가 안내는 사용 지속 시만 |
| N13·N14·N15 | 유효 수행 기간·달성 조건·주간/목표 버전 발송 이력을 확인 |
| N16 | 푸시 없음, 내 변화 보기의 품질 경고로 표시 |
| N17 | 의도적 중지가 아닌 연결 중단 안내, 최소 2시간 간격·하루 최대 3회 |

- 변화 알림은 사용자가 선택한 08·12·21시 슬롯만 사용한다. 다른 종류의 알림 설정에는 영향을 주지 않는다.
- 예약은 Android의 **비정확 알람**이다. 절전·기기 종료·강제 중지에 따라 지연·누락될 수 있으며 정확한 시각 발송을 보장하지 않는다. 30분 이상 늦은 슬롯은 생략한다.
- 보조 알림은 2시간 단위 평가이므로 N04는 최소 60분 조건보다 늦게 발송될 수 있다.
- 재부팅·시각/시간대 변경 후 재예약한다. 로그아웃은 예약·알림을 정리한다. 탭 이동은 현재 로그인 계정과 알림 계정이 같을 때만 처리한다.
- 알림 평가는 로컬 사용량·목표·설정만 사용한다. 알림마다 Firebase나 Gemini를 호출하지 않는다.
- OS 알림 거부·앱 화면 확인 중 생략한 슬롯도 처리 이력으로 남겨 뒤늦게 몰아 보내지 않는다. 잠금화면에는 기본 문구만 공개한다.

## 5. 설정과 삭제

- 기록 끄기: 시간·횟수 측정, 목표 개입, 변화 알림 중지. 접근성 권한을 앱이 임의로 끄지 않는다.
- 콘텐츠 분석 끄기: OCR·서버 카테고리 분류 중지. 시간·횟수와 이를 위한 온디바이스 CV는 유지한다.
- 삭제는 재확인 후 실행하며 계정·목표는 유지한다. 실제 로그인 사용자 경로만 대상으로 한다.
- 먼저 기록을 중지하고 서비스 저장 큐·진행 중 업로드를 기다린다. Firebase 사용 기록 삭제 후 로컬 사용량·미확인 기록·품질 증거와 통계 캐시를 정리한다.
- 오늘 삭제는 해당 월 문서의 하루 필드만 제거한다. 전체 삭제는 월 문서를 100개씩 제한해 삭제한다.
- 실패 시 완료로 표시하지 않고 기록을 중지 상태로 유지한다. 연결 복구 후 재시도할 수 있다. 삭제 후 자동으로 기록을 재개하지 않는다.
- 다른 기기의 미동기화 기록은 이 기기에서 통제할 수 없다. 전체 삭제 전에 다른 기기 측정을 중지해야 한다.

## 6. 저장 범위와 한계

- 기존 Firestore 목표 구조·보안 규칙을 변경하지 않았다. 핵심 목표는 기존 Firebase 동기화를 사용한다.
- 측정 품질, 고정 비교 기준, 연속 휴식 옵션, 발송 이력은 **기기·계정별 로컬 데이터**다. 다른 기기의 목표를 가져와도 비교 기준이 없으면 임의로 복원하지 않는다.
- 오늘 진행 값은 화면을 다시 열 때 읽은 값이다. 실제 한도 판단은 시청 서비스에서 계속 수행한다.
- 저녁 누적 기록과 연속 시청 시간은 관측·체크포인트 단위다. 아직 실제 기기로 경계 시각·절전 상황을 검증하지 않았다.
- 적용 요일·앱별 개별 한도 배분·다음 날 예약 적용은 이번 기본 구현에 포함하지 않는다. 현재는 카드별 선택 앱의 합계 한도와 즉시 적용이다. 기존 명세의 고급 확장 항목으로 남긴다.
- 실제 단말·Firebase에서 예약 발송, 업로드 중 삭제, 재부팅과 계정 전환을 별도 통합 검증하는 테스트 과정 요구됨.

## 7. 주요 모듈

- `domain/HabitInsights.kt`: 유효 날짜·추천 비율·감소량 계산.
- `statistics/HabitInsightsRepository.kt`: 사용량·로컬 품질·화면 켜짐 이력 조합.
- `data/local/HabitStore.kt`: 설정·품질·고정 기준·알림 이력.
- `notifications/HabitNotificationPolicy.kt`: 비교·성과 알림 조건.
- `notifications/HabitAlarmReceiver.kt`: 로컬 예약·중복 방지·안전한 화면 이동.
- `data/repository/DataControls.kt`: 서비스 정산과 삭제 순서 제어.
- 목표·변화·설정 ViewModel/Fragment와 `AppBlockService`: 실제 화면·시청 파이프라인 연결.
